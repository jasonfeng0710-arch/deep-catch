## 5. Risk: Brotli on `application/wasm` is not guaranteed

Cloudflare applies Brotli by content type, and `application/wasm` is **not reliably** in the
default compressible set. Requirement 6 may therefore fail on a stock Pages project. This is
a verify-then-fix step, not something I can promise up front. If the header comes back absent:

- **Preferred:** add a Cloudflare **Compression Rule** for `application/wasm` (dashboard step,
  yours to click — I'll supply the exact rule).
- **Fallback:** ship a pre-compressed `index.wasm.br` with a `_headers` entry setting
  `Content-Encoding: br`. Works, but breaks clients that don't send `Accept-Encoding: br`,
  so I'd only take this if Compression Rules aren't available on your plan.

I'll report the measured header either way rather than assuming success.

## 7. Note: replace committed builds with CI before this gets painful

Committing `build/web/` is a deliberate short-term trade, taken because Cloudflare's build
image has no Godot binary. It has real costs: the `.wasm` and `.pck` are large binaries, every
re-export writes a new copy into git history, and the repo grows monotonically. It's fine
while exports are rare.

**Once re-exports get frequent, replace it with a GitHub Actions workflow** that installs
Godot headless, installs the export templates, runs the export, and publishes `build/web` as
the deploy artifact — via `cloudflare/pages-action` or `wrangler pages deploy`. Then the built
files come out of git history entirely and `build/web/` moves into `.gitignore`. Migrating
later also means a history rewrite (or accepting the dead weight), so the longer this waits,
the more it costs.
